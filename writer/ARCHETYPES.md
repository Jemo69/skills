# Archetypes

Each piece takes exactly one of these four shapes. Follow the template's order and its writing rules.

## 1. The Teardown

For evaluating emerging AI models, developer tools, or infrastructure releases.

1. **The context hook** — bold premise challenging conventional market hype.
2. **The benchmark reality check** — structured comparative data against frontier models.
3. **Hands-on field testing** — real application workloads and edge cases.
4. **Unit economics & efficiency** — token cost, latency, and real financial expenditure.
5. **Tactical critique & culture analysis** — where the provider falls short; actionable feedback.
6. **The verdict** — a clear numerical score or definitive buying decision.

Rules: compare against 2–3 known industry baselines; highlight token consumption (input/output cost per million tokens); anchor testing in multi-step coding, CLI interactions, or backend pipelines.

## 2. The Deep-Dive Technical Manual

For explaining complex programming paradigms, framework migrations, or architectural patterns.

1. **Ecosystem overview & the core bottleneck** — why the tech matters and where common misconceptions arise (state management, overused hooks).
2. **The mental model / core analogy** — a physical or intuitive analogy to anchor mechanics.
3. **Minimal working example** — the simplest viable code snippet.
4. **The anti-pattern breakdown** — explicitly show incorrect or fragile code and its failure modes (race conditions, memory leaks, unnecessary re-renders).
5. **The modern idiom / production solution** — optimized, robust code using modern ecosystem tools.
6. **Summary & framework takeaways** — key recommendations for production adoption.

Rules: introduce every concept with a concrete code example; show the anti-pattern first, explain its failure modes, then present the modern alternative; emphasize composition over boilerplate.

## 3. The Threat Intelligence & Security Briefing

For breaking down vulnerabilities, exploit chains, and software supply-chain risks.

1. **High-stakes threat introduction** — the exploit capability and what makes it dangerous.
2. **Technical anatomy of the vulnerability** — kernel, memory, JIT spraying, or protocol mechanics.
3. **The incident record** — chronological timeline of affected entities.
4. **The developer impact translation** — how servers, databases, or dependencies are exposed.
5. **Actionable defense heuristics** — pragmatic rules: backup strategies, upgrade timing.

Rules: bridge low-level exploits (OpenBSD SACK, FreeBSD NFS, race conditions) to day-to-day developer infrastructure; provide mitigation strategies that don't paralyze development velocity.

## 4. The Conceptual Framework & Trend Forecast

For introducing new terminology, diagnosing industry shifts, and forecasting technology trajectories.

1. **The real-world observation** — a specific conversation or code review anomaly.
2. **Coining & defining the concept** — a concise 1–2 sentence definition of the term.
3. **Root cause deconstruction** — analyzing training data, context limits, or tooling.
4. **Industry projections & market shifts** — forward-looking analysis of where the stack goes next.
5. **Strategic builder advice** — how developers can adapt and maintain taste.

Rules: define distinct conceptual categories (e.g., distinguishing *vibe coding*, *augmented coding*, and *agentic coding*); focus on macro-economic shifts in developer time and token economics.
